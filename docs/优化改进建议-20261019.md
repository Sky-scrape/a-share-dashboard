## 二、总体评价

这是一个**工程质量显著高于典型个人项目**的代码库：安全设计体系化（CSRF/Host 校验/双 token/SSRF 守卫/日志脱敏）、并发纪律严格（锁只护字典、`_PENDING` 哨兵防 Popen 竞态、连接信号量双层归还）、缓存分层清晰（mtime 缓存 + ETag/304 + gzip 槽复用 + LRU 封顶）、"单一来源"纪律贯穿全库、注释里沉淀了大量事故复盘。

**风险不在功能实现，集中在两处**：
1. **工程化护栏缺口**——CI 绿灯不能证明前端与接口契约完好（smoke.py 不被收集）、依赖不锁定、无 lint/类型检查；
2. **量化口径测量的几处定义错误/漂移**——直接影响"策略到底赚不赚钱"这一核心结论的可信度。

## 三、问题清单（按优先级排序）

标注说明：✅ = 已人工回到源码复核；◐ = 子代理证据 + 抽查佐证，建议合入前再确认一次。

### P0 · 尽快处理

**P0-1 CI 从不执行 `tests/smoke.py`——唯一覆盖 API 契约 + 前端结构的测试** ✅
- 证据：`.github/workflows/ci.yml:23` 只跑 `python -m pytest quant/tests tests`；pytest 默认只收集 `test_*.py`/`*_test.py`，`smoke.py` 命名不匹配（README:179 亦自述此点）。仓库无 `pytest.ini`/`pyproject.toml` 可改收集规则。
- 影响：smoke 断言的 `/api/*` 契约、五页元素、路由顺序、落点逻辑等全部脱离 CI 保护；CI 全绿 ≠ 契约完好。
- 建议：CI 增加 `python tests/smoke.py` 一步（脚本自带临时端口起服）；或改名纳入 pytest 收集 + 夹具。依赖外部数据源的部分按现有设计降级 skip，不要静默通过。

**P0-2 依赖不可复现，直接削弱"打包可复现"目标** ✅
- 证据：`requirements.txt` 全部 `>=` 下界、无上界无锁；`.gitignore:38` 忽略 `*.lock`（即使生成锁文件也入不了库）；`打包exe.bat:13` 每次 `pip install -q pyinstaller` 无版本钉。
- 影响：`akshare` 这类高频变更上游一旦改动，CI 与 exe 产物行为漂移且不可回溯。
- 建议：① `pip freeze` 产出 `requirements.lock` 并入库；② `.gitignore` 的 `*.lock` 收窄为具体文件名或显式放行锁文件；③ `pyinstaller==x.y.z` 钉版本；④ akshare 等敏感依赖加上界。

**P0-3 `unsellable_open` 跌停判定与自身文档不符（口径定义错误）** ✅
- 证据：`strategy-iter/scripts/c15_exec_tplus.py:121-123` 实现是「开盘==昨收（容差 1e-6）**且** 收盘==跌停价（容差 EPS=0.005）」；而模块 docstring（L17-18）写的是「**开盘价触及跌停价**时无法开盘成交，改按 T+2 收盘价」。两者是不同的判定。
- 方向修正（复核结论，与子代理原判"偏乐观"不同）：现实现的「平开+收盘封死」被标记后按收盘离场，数值上**偏保守**；漏掉的「一字跌停」用开盘价离场，与被封死的收盘价数值等价或偏保守。**所以不是乐观偏差，而是测量定义错误**：误分类会污染 `exit_kind` 计数与 B/C 口径的语义，且两处容差不一致（1e-6 vs 0.005）。
- 建议：按真实意图改为 `unsellable_open = abs(bar2["o"] - round(rpc*(1-LIMIT_PCT),2)) <= EPS`，统一容差，分列「开盘跌停 / 盘中封死」两类；改后重跑受影响批次并核对计数变化。

**P0-4 确认 T+1 当日止损「诊断口径」在生产与 UI 的标注完整性** ◐
- 背景：生产/研究执行近似允许 T+1 买入当日按 `risk_low` 止损（A 股不可执行），v1.3.5 已新增制度口径（B/C）测量并在看板区分（README:89-93、`c15_exec_tplus.py` 即审计脚本）。子代理报告称"未回写生产"。
- 复核结论：`spec_validate._exec_pnl_realtime` 作为诊断代理保留是设计意图，问题只在**默认口径与标注**——任何仍以 A 口径为主展示的界面/报告，必须固定标注「不可执行的乐观上界」，报告顶部展示 A vs B 差额。
- 建议：排查所有消费 A 口径的 UI/报告出口，统一加标注；新策略决策以 B/C 口径为准。

### P1 · 重要

**P1-1 全仓库无 lint / 类型检查 / 前端静态检查，CI 亦无对应步骤** ✅
- 证据：无 `pyproject.toml`/`ruff.toml`/`mypy.ini`/`.eslintrc*` 等（根目录清单确认）；源码大量 `# noqa: BLE001/E402` 说明按 ruff/flake8 规范书写但未在 CI 固化，规则可被无声破坏。
- 建议：CI 增 `ruff check` + `mypy`（先覆盖 backend 纯函数层）+ 前端 `node --check` 逐个 app.js（或 html-validate）。宽松配置起步、增量收紧，避免一次性大面积红。

**P1-2 策略沙箱白名单是模块级可变全局，逃逸面缺回归保护** ✅（sandbox.py 机制确认；逃逸用例缺口为子代理证据）
- 证据：`quant/quant_sim/strategies/sandbox.py:78` 附近 `_ALLOWED_MODULES` 为普通集合，可运行期整体替换（测试代码即这么用）；现有测试只覆盖 `os/subprocess/open/exec`，未覆盖 `__builtins__`/`__import__`/`__loader__`/`importlib` 逃逸链。
- 建议：白名单改 `frozenset` + 构造期参数化；补逃逸回归用例；文档已披露"防误不防恶、无 exec 超时"的取舍——如需收紧可评估子进程隔离（与 P2 打包自检联动）。

**P1-3 `manifest_mismatch` 只记 metadata 不阻断引擎** ✅
- 证据：`quant/quant_sim/data/loader.py:117-125` 口径不一致仅写入 `panel.metadata["manifest_mismatch"]`，异常路径注释明言"manifest 只增值不阻断"；而同函数 docstring（L73）自述"混入 raw 序列会整体错位且静默，**必须入口拦截**而非跑完再发现"——实现与自述相悖。`backend/quant/quant_api.py` 侧仅拼 UI 提示。
- 建议：`run_backtest` 入口对 `manifest_mismatch` 非空默认 raise（或显式 opt-out 参数）；信号报告增加口径告警段。

**P1-4 策略库存档反序列化健壮性** ✅（store.py:234 已复核）
- 证据：`store.py:234` `s.payload["code"]` 直接下标，坏档 `KeyError` 而非清晰报错；子代理另报 L154-163 覆盖保存时旧档读失败 `except: pass` → version/created 静默重置、L174-193 坏档静默跳过（◐ 建议合入前确认）。
- 建议：payload schema 校验 + 明确错误信息；版本重置显式警告；坏档计数上报 UI。

**P1-5 费用常量复制，违背自家"单一来源"纪律** ✅
- 证据：`c15_exec_tplus.py:34` 刚注释"执行层单一来源（不许复制常量）"import 了 `MF_BUY`，L37 紧接着硬编码 `FEE_MAIN = 0.15`（注释称"与 mf_mono_backtest.FEE 同源"——但同源靠注释不靠 import）。
- 建议：费用收进 `backend/execution_layer.py` 统一 import；报告中注明各口径常量来源。

**P1-6 前端 `href` 伪协议纵深缺口** ✅
- 证据：`web/recap/app.js:655` `<a href="${esc(r.网址)}" target="_blank">`；`esc()` 转义引号但拦不住 `javascript:`/`data:` 伪协议。`网址` 来自 akshare 公告数据原样透传，当前上游是 https 链接、不可利用，但属外部数据直进 href 的纵深缺口。
- 建议：渲染前校验 `^https?://`，否则降级纯文本。可放进 `lib/util.js` 做成 `safeHref()` 单一来源。

**P1-7 `precompute.py` 性能热点** ◐（子代理证据，文件行号已给出）
- 证据：`strategy-iter/engine/precompute.py:73,81-114,195-205` 概念×日期 `iterrows()` 建 dict；`170-180` 每交易日全表 `isin`+`groupby`（O(交易日×行数)）。
- 建议：向量化（MultiIndex+merge / groupby idxmax）；按 date 滚动窗口/差分替代逐日全表扫描。

**P1-8 `quant_payload` 缓存命中仍做 JSON 双向深拷贝** ✅
- 证据：`server_context.py:399,410` 命中 15s TTL 缓存后 `json.loads(json.dumps(cached))` 整包往返；`/api/quant` 总览聚合体量大时每个请求双倍序列化开销。注释自称"浅拷贝"实际是深拷贝。
- 建议：handler 只读不改的话直接返回缓存对象；确需保护则仅在有修改风险的具体路径拷贝。
