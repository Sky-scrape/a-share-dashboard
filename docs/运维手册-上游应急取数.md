# 运维手册 · 上游失败现场采样与应急取数（Lexmount Web Fetch）

定位先说死：**这是人工应急通道，不进生产代码路径、不进任何无人值守链。**
主备源仍可用时一律走正常重试 / 备源轮换 / 缺口兜底；本文解决的是「主备源同时
失效后，白天人工核对与补数」这段空档。

## 背景（2026-10-27 批次）

- 数据链最脆弱的一环是「主备源同时失效」：akshare 封装东财（本网络 push2 直连
  本就不通）、hithink key 有过期/丢失史（2026-09-06、09-15 两次）、腾讯+新浪
  同属公开 HTTP 接口，可能同时被风控或改版。失效发生时最贵的问题是**归因慢**
  ——不知道是限流页、改版页还是本机断网，只能逐个试。
- 因此 2026-10-27 起，出站守卫入口 `backend/netguard.py` 的 `safe_get`（us_market
  美股 57 标的、spec_ohlc_fb OHLC 备源等抓取路径）在**失败分支**自动留「现场采样」：
  状态码 / 异常类型 + 响应体前 2KB，落 `.status/upstream/`（gitignore 内，按
  最新 50 份滚动）。200 的正常响应永不采样，正常轮询零额外 I/O。
  `http_retry.guarded_get` 路径（全球总览 / 东财 / 轮动）暂未挂钩，留待后续批次
  单独接入。
- `chain:us-failed`（凌晨美股抓取失败推送）会附最新一条采样摘要，先看采样
  再动手。`us_market.fetch_kline` 对「200 但 body 非 JSON」的限流页形态
  也单独采样（文件头 `note: json-decode`）。
- Lexmount（此前云端部署的 Web Fetch / Cloud Browser 服务）作为**人工应急
  取数**手段引入：它从云端取回页面内容，可绕开本机网络环境与风控 IP。

## 现场采样怎么看（`.status/upstream/` 最新一份）

| 采样内容 | 判定 | 处置 |
|---|---|---|
| `error: Timeout / ConnectionError` | 本机网络 / 代理问题 | 查代理配置（Clash fake-IP 段 198.18/15 已豁免，见 netguard 头注）；稍后重试 |
| `status: 403/429`，body 含 verify / risk / 验证 | 上游风控 / 限流 | 等冷却窗口；期间用 Lexmount 云端取数核对口径 |
| `status: 404` + HTML body | 接口路径改版 | 对照上游最新接口文档改 URL 模板（模板都是代码内字面量） |
| `note: json-decode`（status: 200） | 200 但 body 非 JSON，典型限流页 | 同风控处置 |

## 应急取数步骤（Lexmount Web Fetch）

1. **先看采样**（上表），确认是「上游侧」失败再走云端取数——本机断网时
   Lexmount 取回了数据本机也写不进库。
2. 确认失败源的 URL 模板（与代码内字面量一致）：
   - 美股日线主源（腾讯，`us_market.KLINE_HOST`）：
     `https://web.ifzq.gtimg.cn/appstock/app/usfqkline/get?param=<SYM>,day,,,<N>,qfq`
   - 美股静态页备源（新浪，`us_market.SINA_HOST`）：
     `https://finance.sina.com.cn/staticdata/us/<sym小写>`
   - 全球总览（fetch_global）同为新浪通道，白名单见
     `backend/global/fetch_global.py` 顶部。
3. 用 Lexmount 的 Web Fetch 取该 URL，得到页面 / 表格内容。
4. **核对要点（Lexmount 实测限制，务必遵守）**：Web Fetch 的表格摘要可能省略
   行、空单元格或丢表头关系——它只用于「核对数值 / 判断上游是否有数」，**不要
   把摘要直接批量写入任何快照**；完整数据以接口原始 JSON 为准。
5. 补数仍走项目自己的路径：白天看板手动重抓 / `python backend/us_market.py`；
   缺口池由下一次完成链自动补跑（缺口扫描兜底，近 6 个交易日）。已有终版池
   快照**禁止** `--force` 回补（复盘快照冻结纪律）。
6. 采样目录不用手工清理：`.status/upstream/` 自动滚动保留最新 50 份。

## 为什么不把 Lexmount 接进代码（决策记录）

- 出站 HTTP 全站统一走 `guarded_get`（https + 主机白名单 + SSRF 阻断 + 禁重定向），
  `tools/check_outbound.py` 在 CI 挡裸调用；接云端服务必须加白名单，是一次
  安全面扩张。
- 无人值守链要求「失败可重试、结果可核验、口径可追溯」；云端取页的表格摘要
  会省略行（实测），不满足口径严谨要求，只能当人工核对工具。
- 多一个外部凭据 / 费用 / 可用性依赖，收益只覆盖「主备源同挂」的低频场景
  ——人工应急即可，不值得常驻代码路径。
