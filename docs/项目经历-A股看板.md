## 面试展开版（背景 → 难点 → 方案 → 结果）

### 一句话定位
一个从个人真实需求长出来的系统：把"每天盯盘要看的所有事"压进一个入口，并把"看 → 判断 → 下单参考 → 复盘验证"做成每日自动运转的闭环。不是 demo，是每天在跑的生产系统。

### 背景
- 痛点：盘中信息散落在行情软件、涨停池、竞价数据、外盘等多个来源，来回切换容易错过关键窗口；盘后复盘靠手工整理，策略想法无法快速验证。
- 目标：单服务、单端口、单入口；数据可信（P0）→ 盘中不被噪音打断（P1）→ 结论站得住（P2），三层各自解决一个问题。

### 架构与关键设计
- **单体自研 HTTP 服务**（Python 标准库，无 Web 框架）：路由表化，HTTP 层零业务计算，只做校验与序列化；前端为原生 JS + ECharts 多页应用，公共组件（顶栏/主题/新鲜度胶囊）抽成共享库。
- **三层能力模型**：数据基石（健康监控 + 兜底 + 自愈）、体验闭环（自动跟踪 + 预警 + 一键导出）、深度分析（情绪指数 + 轮动统计 + 备选池）。情绪指数公式带权重版本号，历史面板可回溯。
- **单一来源原则**：交易日历（8 位口径）、个股→行业映射、东财常量、HTTP 重试、执行层常量、顶栏页序、启动落点等每件事只存一处——这是项目规模膨胀到 4.5 万行仍能低 bug 率迭代的核心手段。

### 数据与可靠性工程（最有故事的部分）
- 8 条 Windows 计划任务链路按交易日时序编排：04:05 美股收盘链（含备选池生成）→ 08:40 全球总览 → 09:14 竞价逐轮（09:15–09:24:30 每 30s）→ 09:25 盘中逐分钟轮询（收盘定格）→ 17:05 复盘 + 17:10 轮动兜底 → 12:10 滚动备份 → 每 15 分钟看门狗。
- **计划任务四个静默坑**（实挂排查复盘）：npm 包的 .cmd shim 在 bat 里必须 `call`，否则后续步骤整段静默断掉；默认电源策略在电池供电时秒杀任务（LastTaskResult=255 且零日志）；bat 写中文注释会因 GBK 解析吞换行；`IdleSettings` 空闲条件导致"用户盯盘 = 永不空闲 = 任务全天不跑"。
- **上游竞态事故**（0914）：上游数据源 T 日 release 约 17:11 发布，而 17:05 的 sync 抢跑漏赶，导致 T 日日线整层缺失、量能指标用了错日口径。修复：新增腾讯前复权日线备源 + 层探测状态落盘 + 新鲜度告警 + 校验器拒用错日数据。
- **告警闭环**：从"打开看板才知道出问题"到"手机先知道"——health 巡检线程每 10 分钟扫描（断流/缺层/过期/备份异常），key 级 6h 节流，Server酱/企业微信/Telegram 三选一。

### 量化引擎与策略自迭代
- 事件撮合引擎支持 T+1、涨跌停、整手、佣金/印花税、滑点、参与率约束；115 项回归测试 + 冒烟测试（起临时 server 断言 API 契约），CI 全绿。
- 策略自迭代：三轮全区间迭代收敛 C_Final（胜率 59.75%、均次日 +2.13%、最大回撤 -1.99%）；主梯度因子是概念内涨停家数。
- 防过拟合三件套：结构规则/环境配额/执行层永不自动改动；调参限定 45 日滚动窗口内的有界调整且全部留痕可重放；样本外追踪 + 20 日到期复审，胜率回落自动告警建议重开迭代。
- 资金曲线回测把条件期望换算成纪律执行的组合曲线：累计 +62.03%、年化 +106.87%、最大回撤 -38.85%（回测口径）。

### 产品化交付
- PyInstaller 双形态打包（onefile 秒装版 / onedir 秒开版），按构建指纹增量同步源码与数据到 LOCALAPPDATA，升级换 exe 即可、用户数据保留。
- 桌面窗口用 pywebview + 系统 WebView2：无终端黑窗、标题栏颜色随页面主题即时切换、窗口尺寸位置记忆、外部链接自动移交系统浏览器、关窗连带杀掉全部派生抓取子进程。
- 移动端经 Tailscale 私有通道访问，390px 视口适配 + gzip 省流量。

### 结果
- 一个月独立交付 v1.0，此后按"每日使用 → 发现问题 → 当日修复"的节奏持续迭代（git 历史 30+ 提交、每条事故都有修复与防回退测试）。
- 系统成为每日盯盘的实际工作台：采集、告警、备选池、验证归因全自动运转，人工只做最后的决策执行。
