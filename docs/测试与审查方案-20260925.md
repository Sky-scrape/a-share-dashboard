## 6. L3 横切审查

### 6.1 安全（netguard 深审 + 既有防线抽测 + gui.py 新表面）

netguard 设计审查结论项（逐条给出 接受/整改 判定）：

- **TOCTOU / DNS rebinding**：`check_url` 解析校验与 `requests.get` 实际连接之间存在解析再变窗口。
  直连场景理论存在；代理场景实际解析发生在代理侧（按 hostname 路由）。判定建议：**记录为已接受
  风险**（第 2 层本就自述为「纵深防御」，第 1 层白名单才是控制面），可在 docstring 补一句声明。
- **代理信任（trust_env）**：`requests.get` 默认信任 `HTTP(S)_PROXY`——豁免场景成立正依赖于此。
  审查确认代码未显式 `session.trust_env=False`（禁了反而破坏代理用户）→ 行为正确，补注释固化意图。
- **重定向**：`allow_redirects=False` 是防线一部分 → G1 用例固化，防止未来有人「顺手」打开。
- **白名单传参纪律**：确认 `us_market._ALLOWED_HOSTS`、`spec_ohlc_fb._ALLOWED_HOSTS` 均为模块级
  字面量集合，无任何外部输入拼接（grep 调用点）。
- **diagnose 的 `__main__` hosts 与真实白名单漂移**：硬编码了 3 个主机，建议改为 import 两个模块的
  `_ALLOWED_HOSTS` 取并集（低优先级改进项）。

### 6.4 Python 版本矩阵
