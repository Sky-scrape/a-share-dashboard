# C19：同花顺 Fuyao API 数据能力盘点与实测

- 日期：2026-11-03
- 起因：用户提供 https://fuyao.aicubes.cn/docs/api-reference/overview/ ，要求评估「其他数据有没有用」
- 结论先行：**最有价值的三类数据（筹码形态、主力资金流、高频分时）被锁在客户端，API Key 调不通；
  能调通的两类里，「竞价信号」提供了一个两段一致的负面因子，「涨停统计」做不了择时。**

## 一、API 可用性实测（不是看文档猜，是逐个打过）

用现有 API Key（`hithink-finance` 同一套凭证）逐一请求，结果：

| 数据 | 端点 | 实测结果 | 判断 |
|---|---|---|---|
| **筹码形态** | `/special-data/chip-shape-dates` | `code=2004` 客户端专用 | ❌ 不可用 |
| **主力资金流**（超大/大/中/小单，日级历史） | `/capital-flow/historical` | `code=2004` 客户端专用 | ❌ 不可用 |
| **高频分时** | `/high-frequency` | 文档标「已接入客户端」 | ❌ 不可用（同类） |
| **涨停市场统计** | `/special-data/limit-up-statistics` | `code=0` **有历史** | ✅ 可用 |
| **竞价机会** | `/special-data/auction-stock-opportunities` | `code=0` **有历史** | ✅ 可用 |
| 龙虎榜机构详情 | `/special-data/dragon-tiger-stock-institution` | `code=0` | ✅ 可用 |
| 营业部战绩 | `/special-data/dragon-tiger-department-...` | 需 department_id，不支持按日期 | ⚠️ 半可用 |
| 财务/基金/期货/期权 | `/financials` 等 | 可用 | ⭕ 与短线无关 |

**最遗憾的一条**：主力资金流（超大单/大单/中单/小单的日级净流入历史）正是我前几轮反复说
「缺资金痕迹」的那个东西，文档写得很完整、字段设计得也够用，但**权限被锁在客户端内**。
如果后续能拿到这个权限，它是目前所有数据里对短线最有价值的一项——它直接给出「谁在买」。

## 二、涨停统计：可用、有历史，但做不了择时

抓了 7-10 月 82 个交易日。字段：封板率 `seal_rate`、炸板数 `open_stock_count`、
涨停数、各板级家数与晋级率、精确连板分布。质量很好。

**问题是它跟次日收益没有关系**：

| 指标 | 与次日全市场收益的相关性 |
|---|---:|
| 封板率 seal_rate | +0.059 |
| 炸板率 | −0.059 |
| 二板晋级率 | −0.106 |
| 涨停家数 | −0.049 |
| 最高板高度 | +0.160 |

分档也不单调：低封板日 −0.656%、中封板 +0.126%、高封板 −0.289%；
少炸板 −0.336%、中 +0.152%、多炸板 −0.647%。

月度上看更清楚——10 月封板率最低（0.668）且收益最差（−0.689%），但 7 月封板率也不高
（0.712）收益同样差（−0.314%），而 8 月封板率最高（0.777）收益为正（+0.145%）。
**没有可用的单调关系，我原本想用它做「准入闸门」的设想不成立。**

## 三、竞价信号：这里有一个真东西

抓了 1640 条竞价信号（82 天 × 每天 20 条），匹配到行情 1350 条。信号类型分布：
竞价抢筹 1014、竞价砸盘 428、大幅低开 74、大幅高开 45、买一/卖一剩余大 53、急速上涨 26。

### 最反直觉的发现：叫「抢筹」的，第二天是跌的

| 信号 | n | T+1 开盘 | T+1 收盘 | T 日收盘买→T+1 收盘卖 | 训练 7-8 | 验证 9-10 |
|---|---:|---:|---:|---:|---:|---:|
| **竞价抢筹** | 817 | −0.35% | −0.34% | **−0.49%** | −0.10% | **−0.85%** |
| **竞价砸盘** | 363 | −0.37% | +0.14% | −0.01% | +0.21% | −0.30% |
| 大幅高开 | 34 | +4.00% | +2.31% | +2.16% | +0.74% | +3.15% |
| **大幅低开** | 62 | −2.39% | −1.89% | **−2.04%** | −2.73% | −1.35% |
| 全部信号 | 1350 | −0.34% | −0.23% | −0.38% | −0.11% | −0.63% |

**竞价抢筹两段都为负（−0.10% / −0.85%），且样本 817 条**——这是继「追高必亏」之后
又一个方向稳定、量级可观的负面因子。名字叫「抢筹」，实际含义是「竞价阶段有大量资金
高价挂单抢货」，结果第二天接盘的全是亏的。这与前面「高换手、高涨幅、高量比」全部为负
是同一个机制：**情绪最热的那一刻就是卖点**。

「大幅低开」两段也都负（−2.73% / −1.35%），也是一个可用的排除项。

### 但也有三个「训练段有效、验证段失效」的

| 信号 | 训练 7-8 | 验证 9-10 |
|---|---:|---:|
| grade=3 | **+0.70%**（n=72） | −0.17%（n=54） |
| 竞价额/前日成交额 > 75 分位 | **+0.66%**（n=165） | −0.31%（n=163） |
| 竞价砸盘 | +0.21% | −0.30% |

这三个跟前面六轮里那些「训练段漂亮、验证段翻负」的因子是同一类东西，**不能采用**。

### 覆盖面是硬伤

竞价接口每天只返回 **20 条**，覆盖不到全市场（3000+ 只）。所以它**不能当选股器**，
只能当**过滤器**：当你已经决定要买某只票时，查一下它今天有没有竞价抢筹/大幅低开。

好在竞价数据是 **T 日 9:25 就确定**的，比收盘后的龙虎榜、人气榜更及时，用于 T 日
收盘买入的决策时点上完全合法，不存在前视问题。

## 四、这一轮的净收获

1. **数据能力边界摸清了**：三样最想要的数据（筹码/资金流/分时）锁在客户端；
   能用的增量只有涨停统计和竞价信号。
2. **涨停统计不能做择时**（相关性 r<0.16，分档不单调），我原本想拿它做准入闸门的想法被自己的数据否掉了。
3. **竞价抢筹是一个可在生产里直接用的负面过滤器**：两段一致为负、样本 817 条。
   规则只有一句：**今天竞价被标记「抢筹」的票，收盘不要买。**
4. **又一次复现了同一个模式**：训练段有效、验证段翻负的因子（grade3、竞价额占比、
   竞价砸盘）——说明「7-8 月有效」这件事本身极不稳定，任何只在训练段成立的信号都不该上线。

## 五、如果想让这套数据真正发挥作用

按价值排序：

1. **争取主力资金流权限**。这是唯一能回答「谁在买」的数据，也是我这几轮反复证明的
   唯一还没试过的维度。没有它，所有分析都停留在价格和成交量的派生量上。
2. **把竞价抢筹接进生产**——成本极低（一次 API 调用/天），规则明确，且两段验证过。
   它不会让策略赚钱，但能避免在情绪最热的票上接盘。
3. **用 11-12 月数据做真样本外**，验证前面所有结论（尤其是「小市值 + 负面清单」）。
